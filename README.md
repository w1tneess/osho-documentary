# Osho Rajneesh — A Documentary

An evidence-based interactive documentary on Osho Rajneesh (1931–1990), built as
semantic HTML over a scroll-driven 3D world.

The documentary is the product. The 3D world is the room it is shown in, and the
two are staged together rather than stacked: one shared score declares, per
narrative beat, where the text sits in the frame and where the 3D subject sits
opposite it. The only thing crossing between the DOM and the canvas is normalised
scroll progress.

## The score

`src/entities/chapter/chapters.ts` is the single source of truth for how the world *looks*
at every narrative movement. It is not a list of scene switches — every field is
interpolated continuously by scroll progress, so the world evolves rather than
being replaced.

One entry per narrative movement (opening, nine chapters, conclusion, sources).
Each declares:

- **camera** — position, look-at, a per-shot `fov`, and a `subjectShift` that
  pans the 3D subject into whichever third the editorial column is not using;
- **sky** — a three-stop vertical gradient plus a real sun placed from azimuth
  and elevation, so the visible disc always agrees with the directional key;
- **atmosphere** — exponential-squared fog density, which is both the aerial
  perspective and the depth gate that isolates each chapter's subject;
- **light** — key, hemisphere fill, and a rim. The key-to-fill ratio is asserted
  by the content validator because a ratio near 1:1 is exactly what "flat" means
  in lighting;
- **grade** — tone-mapping exposure and vignette strength;
- **composition** — which side the editorial column occupies.

### The DOM/canvas contract

A section declares which score entry it belongs to via `data-score`, and the
scroll engine interpolates between them. The hero and the prologue both belong to
entry 0, so the camera holds its frame while the reader is on the opening spread
instead of sliding on at a rate nobody asked for.

A beat's `layoutMode` decides three things at once: which grid columns the
editorial column occupies, where the directional scrim is anchored, and where the
camera pans the 3D subject. `beatComposition.ts` is the single translation table
between the DOM's editorial vocabulary and the score's spatial one, so the text
and the world can never disagree about which side of the frame they are on.

### Performance

The documentary and the 3D world ship as separate chunks. `SceneCanvas` is
dynamically imported, so the entry chunk carries the entire documentary and the
world streams in behind it — and never reaches a device that cannot draw one.
Arches over 240KB gzipped, the entry payload is roughly 96KB.

There is no post-processing chain. A vignette belongs over the whole frame, DOM
included, which a post pass cannot reach; both it and the film grain are CSS
compositor layers driven from the same score.

## Verification

`npm run validate:content` runs 565 assertions covering the score's structural
and tonal invariants, chapter and beat integrity, image roles and credits,
deployment files, and the `index.html` metadata. It is chained into `npm run
build`, so a structural regression fails the build rather than shipping.

`node scripts/audit-css.mjs` reports CSS class rules and custom properties with
no reference anywhere in `src/` — dead stylesheet surface is otherwise invisible.

## Accessibility

Verified in a real browser across the full validation matrix: one `h1`, no
heading-level skips, a skip link as the first tab stop, a visible focus ring, a
focus-trapped index drawer that restores focus on close, `prefers-reduced-motion`
revealing all content, and a `prefers-reduced-motion` / no-WebGL / print
stylesheet that leaves the documentary readable and complete.

## Deployment

Static, no server runtime. `vercel.json` pins the framework, the build command
and the output directory, and sets immutable caching for hashed assets. SPA
routing is not required — the documentary is one route with in-page anchors.

## Content integrity

`src/entities/content/documentary.ts` is the source of truth for the text and is not
modified by the presentation layer. `evidence` marks whether a block is a fact
from the record, a quotation, or the documentary's own analysis; the UI renders
a mark only when the content declares one, and never labels a claim the source
does not support. Images are credited inline.
